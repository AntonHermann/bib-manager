## Decision

Rule: `bench/README.md`, section "Decision rule (step 0a)". Provenance of the backends:
`libpdfium` downloaded from the pdfium-binaries releases (`releases/latest`), build see the
backend list above (155.0.8057.0); `mutool` 1.25.1 is the system binary.

- R: pdf_oxide 20/21 ≈ 0.9524, pdfium 18/21 ≈ 0.8571, mutool 21/21 = 1.0000, pdf-extract 21/21 = 1.0000
- O: pdf_oxide 7/7 = 1.0000, pdfium 7/7 = 1.0000, mutool 7/7 = 1.0000, pdf-extract 7/7 = 1.0000
- Documents with character issues for pdf_oxide: dwork2006 (ε missing), shokri2017 (ε missing);
  control characters, `(cid:`, and U+FFFD in no document — covered by pdf-extract: yes
  (dwork2006 and shokri2017: no missing characters, 0 control characters, 0 `(cid:`, 0 U+FFFD)
- **Default backend:** pdf_oxide  **Cascade on suspicion:** pdf-extract

Check, rule 1 (pdf_oxide):

1. R(pdf_oxide) = 20/21 ≥ max(18/21, 21/21) − 0.05 = 1 − 0.05 = 0.95.
   Exactly: 20/21 = 400/420, 0.95 = 399/420, so satisfied (margin 1/420 ≈ 0.0024).
2. O(pdf_oxide) = 7/7 = 1 ≥ max(7/7, 7/7) − 0.05 = 0.95, satisfied.
3. Character condition per document: pdf_oxide has missing characters only in dwork2006 and
   shokri2017 (ε in each case), otherwise no control characters, `(cid:`, or U+FFFD. pdf-extract
   provides all expected characters in both documents, satisfied.

Rule 1 applies; rules 2 and 3 are no longer checked. For context: pdfium would already have
failed rule 2 on R (18/21 ≈ 0.8571 < 0.95).

The margin in condition 1 is tight: one more missed sentence (19/21 ≈ 0.9048) would have flipped
the rule for pdf_oxide.

### Observations

- **pdf_oxide, vaswani2017, sentence (a)** ("The dominant sequence transduction models …"): the
  heading "Abstract" appears in the extracted text between the first and second lines of the
  paragraph ("… complex recurrent or⏎Abstract⏎convolutional neural networks …"). The line order
  is disrupted, not the characters; pdf-extract and mutool place the heading before the
  paragraph.
- **pdfium, abadi2016, sentence (b)** ("Deep neural networks, which are remarkably effective …"):
  hyphenation at the line break comes through as U+0002 instead of a hyphen ("parameterized
  func\x02⏎tions"). Normalization only joins `-` at line breaks, so the word stays split.
- **pdfium, devlin2019, sentence (a)** ("We introduce a new language representation model …"):
  same cause, "representa\x02⏎tion".
- **pdfium, devlin2019, sentence (c)** ("In particular, these results enable even low-resource
  tasks …"): same cause, "architec\x02⏎tures".
- Of pdfium's 1128 control characters, most in the recounted documents are these U+0002 split
  markers: devlin2019 332 of 332, abadi2016 195 of 241 (remainder U+0001, U+0003,
  U+0012–U+0015, U+001D).
- mutool's 191 U+FFFD come predominantly from abadi2016 (163).
- pdf-extract provides no geometry (0 pages with geometry in all documents); as a cascade it
  only contributes text, positions remain with the default backend.
